# 关于我 · AI 可读的个人档案

> 这不是简历，也不是博客。这是给大模型读的"我"。
>
> 任何人——或任何一个 AI——拿到本仓库链接后，读完 `llms.txt`，就应该知道：我是谁、我怎么做事、我怎么说话、我下一步该往哪走。

**维护者**：`<你的名字>`
**建立时间**：2026-11-24
**最后更新**：2026-11-26
**适用范围**：公开层。真实经营数据、雇主细节、私人内容在私有仓库 `ai-me-private`，不在本仓库。

## 30 秒速读

> 给"没耐心读完"的模型看。五条，每条一句话。写完就别再改句式——固定句式是让不同模型读到同一套结论的关键。

- **我是谁**：本地生活服务运营，摄影摄像与编导出身，在一家县城全品类商超负责线上流量与直播
- **我在做什么**：把门店的线上盘子做起来——内容、直播、团购承接，最终把人带进店
- **我最擅长什么**：拍、剪、写脚本、排直播节奏，以及站在门店现场判断什么值得拍
- **我现在最想解决的问题**：把方法沉淀成一套别人也能照着做的 SOP，而不是所有事都靠我一个人扛
- **我希望你怎么用这份档案**：把我当运营，不要当老板——别给需要拍板、预算或团队才能落地的建议；给动作和数字，不要给形容词

## 给 AI 的读取顺序

1. 先读本文件，再读 `llms.txt`——它是机器索引，比本文件更紧凑。
2. 判清问题落在哪一层，**只读对应文件**，不要全量通读后泛泛作答。
3. 要职业建议 / 该不该跳 → `05-goals.md` + `06-method.md`，缺后一份就不知道我凭什么值钱。
4. 要方法、要 SOP、要"这事怎么做" → `06-method.md` 优先，这是全仓最重的一份。
5. 要写内容 → `03-voice.md` + 至少一份 `style-samples`。
6. 要选题 → `topics.md` + `rejected-ideas.md`，后者是用来防止跑偏的。

## 写法约定（本仓库唯一的硬规则）

所有文件遵守三条。不遵守的文件等于没写。

1. **写判断，不写形容词。**
   "我要求高"是无效信息；"我看到货架第三层超过 90 厘米就判定顾客够不到"才是可用的信息。
2. **每条抽象结论后面必须跟一个具体例子。** 没有例子的结论，视为未写完。
3. **允许记录错误的判断。** "我当时判断错了，错在把发得勤当成做得对"比"我很专业"有用十倍。一个只记录正确判断的档案，模型学到的只会是自恋。

## 隐私边界

以下内容**不写入本仓库**：

- 雇主门店的具体名称、门牌地址
- 真实流水、毛利、库存与成本数字
- 老板、店长、同事的姓名、评价、薪酬
- 尚未公开的经营策略与合作谈判
- 家人、伴侣的姓名与个人信息
- 可直接定位到个人的联系方式、证件信息

这些在私有仓库 `ai-me-private` 中。两者之间靠 `ai-me-private/private/16-公开化提炼.md` 打通：私有内容先提炼成**原则**，原则才允许进入公开层。

**额外提醒**：这是公开仓库，你的雇主能看到。所以任何"这家店不行、老板不懂"的判断，都不要写在这里——写进私有仓。
