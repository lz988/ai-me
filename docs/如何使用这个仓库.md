# 如何使用这个仓库

> 目标：让任何一家大模型，在 30 秒内变成"读过你档案的人"。

---

## 三种投喂方式，按可靠性从低到高

### 方式 A：贴仓库首页链接（最省事，但不可靠）

```
请先读取这个仓库里的 llms.txt 和 AGENTS.md，再按问题类型读取对应文件：
https://github.com/<你的用户名>/ai-me
```

- **适用**：能联网抓网页的模型
- **问题**：很多模型抓到 README 就停了，读不到子目录里的文件
- **结论**：只在你确认它确实读到了子文件时才好用

---

### 方式 B：贴 raw 纯文本链接（境外模型推荐，国内可能受限）

GitHub 每个文件都有一个"原始文本"地址，格式固定：

```
https://raw.githubusercontent.com/<用户名>/<仓库名>/main/<文件路径>
```

例：

```
https://raw.githubusercontent.com/<用户名>/ai-me/main/llms.txt
https://raw.githubusercontent.com/<用户名>/ai-me/main/profile/03-voice.md
```

- **优点**：返回的是纯文本，任何能访问网页的模型都能完整读到，不会被网页壳干扰
- **做法**：一次贴 2–3 条最相关的 raw 链接，不要一次贴十几条
- **提示**：仓库默认分支如果是 `master`，把 `main` 换成 `master`

> **国内网络实测（2026-11-24）**：`raw.githubusercontent.com` 在国内大部分网络下会被 SSL 拦断，本机实测不可达；`cdn.jsdelivr.net` 同样不通。
>
> 也就是说：**这条最好用的路径，恰好是国内最不通的。** 如果你打不开 raw 链接，按下面顺序退：
> 1. 直接开仓库页面 `https://github.com/lz988/ai-me`（这个能开，但模型要自己点进子目录，很多模型不会点）
> 2. 用方式 C，把文件内容粘进对话——**国内模型这是唯一可靠的方式**
> 3. 如果长期主要用国内模型，最省事的做法是把公开仓再镜像一份到 Gitee 或 CNB，国内直连无阻

---

### 方式 C：直接粘贴内容 / 上传附件（最稳）

把 `llms.txt` + 需要的那 2 份 profile 文件，直接粘进对话，或者存成文件上传。

- **优点**：零网络依赖，任何模型都吃得到
- **缺点**：每次要手动搬
- **建议**：把 `llms.txt` 存在手机备忘录里，随用随贴

---

## 不要一次把所有文件都喂给模型

这是最常见的错误。喂 8 份文件进去，模型会把它们融合成一篇"综合画像"，然后给你一篇综述——你损失了全部精度。

**正确做法：按问题类型只喂 2–3 份。**

| 你的问题 | 该喂哪几份 |
| --- | --- |
| 这个月该做什么 / 优先级怎么排 | `llms.txt` + `05-goals.md` + `02-thinking.md` |
| 短视频选题 / 脚本 | `topics.md` + `03-voice.md` + `sample-01.md` |
| 门店改造 / 陈列 / 动线 | `04-business.md` + `rejected-ideas.md` |
| 要不要开新店 / 要不要转行 | `05-goals.md` + `02-thinking.md` + `04-business.md` |
| 帮我写一段话，要像我说的话 | `03-voice.md` + 两段语料 + `sample-01.md` |
| 我这件事是不是想错了 | `01-beliefs.md` + `02-thinking.md` |

## 可复制的自定义指令

把下面这段存成你的常用开场白，或填进各家的「自定义指令 / 系统提示」里。**这段是整套东西的开关。**

```
你是一名读过我全部个人档案的长期顾问。档案在这个仓库：<仓库链接>

工作方式：
1. 回答前先判断我的问题属于哪一层（经营 / 个人规划 / 内容创作 / 认知），只读取对应的 2–3 份文件，不要全量通读。
2. 结论先行，第一句话给判断，不要铺垫。
3. 每条建议必须对应我档案里写明的一个真实约束（预算、人手、渠道、时间、已放弃的路）。
4. 如果我的想法撞上档案里记录的盲区或失败模式，先点出来，再给替代方案。
5. 档案没写的，直接说"档案里没有，需要你补充"，不要用一般情况填充。
6. 不要复述我的档案，不要给无成本建议（如"要重视用户体验"），不要把我美化成一个已经成功的人。
7. 我当次说法与档案冲突时，以当次为准，并提醒我更新档案的具体位置。
```

## 各平台的实际用法

| 平台 | 怎么用 |
| --- | --- |
| 支持联网的对话模型 | 用方式 A 或 B，贴链接 |
| 支持上传附件的 | 用方式 C，上传 md 文件 |
| 支持自定义指令 / 全局设定的 | 把上面那段填进去，之后每次对话不用再贴 |
| 不联网也不支持附件 | 只贴方式 C 的纯文本，一次贴 2 份 |

> 一个实用顺序：**先让模型读 `llms.txt` 和 `AGENTS.md`，让它自己决定还要读什么。** 聪明的模型会主动问你要 `03-voice.md`；笨的模型会直接开始瞎答，这本身就是一次筛选。

## 维护节奏

| 频率 | 做什么 |
| --- | --- |
| 每周 | 写一条思考卡片到 `journal/` |
| 每月 | 更新 `05-goals.md` 的卡点状态；回填 `topics.md` 的数据 |
| 每季 | 复查 `01-beliefs.md`，**删掉你已经不信的条目** |
| 随时 | 遇到一个"我早说过不要这样"的时刻，立刻加进 `rejected-ideas.md` |

**档案的价值不在写得多，在写得准。** 一份 2000 字但是真实的档案，比一份 20000 字充满形容词的档案，对模型有效十倍。

---

## 五个常见坑

1. **写成简历**。简历是给别人看的，档案是给模型推理用的。删掉所有"擅长沟通、责任心强"。
2. **只写优点**。不写失败和盲区的档案，模型只会顺着你说话，你就失去了它最有价值的部分。
3. **把私有内容放公开仓**。一旦公开就是永久的，搜索引擎会缓存。真实数字、家庭信息，一律进私有仓。
4. **一次写太多，然后三个月不更新**。模型的时效感依赖 `最后更新` 字段和你 journal 的日期。空转的档案会让它给出过时的建议。
5. **不给 AI 行为约定**。只有内容没有 `AGENTS.md`，模型仍然会用它的默认习惯回答你——那么你辛苦建的人设，会被它的套话抵消掉。
